# KIDFORUM 系統設計說明

**整合「會考派題 × KIDMAP 診斷」與「Knowledge Forum 知識建構」的 AI 助評原型**

版本 0.1 · 研究原型

---

## 1. 整合主張

兩個來源平台各自完成了一半的工作。

**會考派題平台（preview-60plrtfiynlj.kusesite.com）** 能精準指出「誰在哪一個概念上卡住」：
照康軒單元派會考題、用簡化 Rasch 模式估出試題難度與學生能力、再用 KIDMAP 四象限把
「能力足以答對卻答錯」的格子標出來。但它的終點是一份給老師看的報告加上 AI 教學建議；
學生始終是被診斷的對象，診斷結果轉不轉成理解，取決於老師接下來做了什麼。

**Knowledge Forum（knowledgeforum.org, KF6）** 把知識推進的權力交回學生手上：
視圖（view）是共同的白板，貼文用支架（scaffold）表明自己在做什麼，
可以延伸（build-on）、挑戰、躍升（rise-above）、引用。但 KF 沒有辦法回答
「今天最該討論的是哪一個問題」——起始問題通常靠教師的直覺，
而討論最後有沒有改變學生的理解，也很難用 KF 自己的指標證明。

KIDFORUM 的設計主張只有一句話：

> **讓測驗診斷成為知識建構的問題來源，讓知識建構成為測驗診斷的介入手段，
> 再用 AI 助評把兩邊的資料翻譯成教師與學生都能行動的語言。**

對應到 Scardamalia 的知識建構第 12 項原則「同步、內嵌、轉化的評量」
（concurrent, embedded and transformative assessment）——這條原則在多數系統裡只是口號，
本系統試圖把它做成可運作的機制。

## 2. 系統迴圈

```
① 派題（康軒單元 → 會考題組，含選擇題與非選題）
    ↓
② 學生作答（線上作答；非選題可手寫）
    ↓
③ KIDMAP 診斷（簡化 Rasch → δ、θ → 人×題 四象限）
    ↓
④ ★ 迷思橋接（第 II 象限的題目一鍵開成知識建構視圖）
    ↓
⑤ 知識建構（支架貼文 → 延伸 → 挑戰 → 躍升）
    ↓
⑥ AI 助評（貼文形成性回饋／想法串綜整／社群報告）
    ↓
⑦ ★ 由討論命題（共同理解 → 新題目）
    ↓
⑧ 共構後測（Δθ × KB 指數 雙軌檢核）→ 回到 ①
```

④ 與 ⑦ 是本系統獨有的兩個接點。少掉任何一個，系統就退回原本的兩個平台。

## 4. 演算法規格

### 4.1 簡化 Rasch 模式（JMLE）

單參數 logistic 模式：

```
P(X_ni = 1) = 1 / (1 + exp(−(θ_n − δ_i)))
```

* 起始值以 PROX 取得：`θ = ln(r / (L − r))`、`δ = −ln(s / (N − s))`
* 交替 Newton–Raphson：
  `θ_n ← θ_n + (r_n − E_n) / Σ p(1−p)`、`δ_i ← δ_i + (E_i − s_i) / Σ p(1−p)`
* 每回合單步限幅 ±1 logit，避免發散；收斂門檻 1e-4，最多 120 回合
* 極端分數（全對／全錯）以 ±0.3 分校正（Wright 慣例）
* 每回合把試題難度平均中心化為 0，設定量尺原點
* 標準誤 `SE = 1 / √Σ p(1−p)`
* 適配度：`Infit MNSQ = Σ(x−p)² / Σ p(1−p)`、`Outfit MNSQ = mean[(x−p)² / p(1−p)]`

**假設與限制**：等鑑別度、單一向度、無局部相依、無猜測參數。小樣本時估計不穩，
系統預設至少 3 人完成才執行（可在設定調整）。

### 4.2 KIDMAP 四象限

以 `θ_n > δ_i` 定義「預期答對」：

| | 答錯 | 答對 |
| --- | --- | --- |
| **δ > θ（難題）** | III 合理答錯 | **I 優勢概念** |
| **δ < θ（易題）** | **II 迷思概念** | IV 合理答對 |

第 II 象限是整個系統的樞紐：它不是「答錯的題目」，而是
「照這位學生的能力本來應該答對、卻答錯」的題目——最可能來自穩定的錯誤概念，
也最值得整班一起想清楚。

圖形表徵（`kidmapSVG`）刻意採用 KIDMAP 原始的呈現方式：
縱軸為試題難度、橫向分成答錯／答對兩欄、中間一條水平虛線標出該生的 θ。
全班四象限的統計卡片也按同樣的空間位置排列（左上 III、右上 I、左下 II、右下 IV），
讓兩種表徵可以互相對照。

### 4.3 迷思橋接的觸發與產出

**觸發條件**：某題的第 II 象限人數 ÷ 該題作答人數 ≥ 門檻（預設 15%，可調）。

**產出物**：

1. 一個新的知識建構視圖，標題是一個**問題**而不是一個主題
   （若該題誘答有掛迷思代碼，標題為「『<迷思名稱>』什麼時候會出錯？」）
2. 一則「全班共同問題」貼文，使用「我需要理解」支架，內容包含：
   落在第 II 象限的人數、最多人選的誘答選項與人數、對應的迷思概念描述、
   以及一段刻意寫成「請說出你原本怎麼想」而不是「請訂正」的指示語
3. 一則「知識資源人」貼文，列出在該題落在第 I 象限的同學，
   請他們先貼出自己的思路，而不是直接給答案
4. 視圖的 `origin` 欄位記錄 `{aid, iid, mis}`，讓討論可以往回追到原始題目

### 4.4 論述層次（1–4 級）

規則判定，完全可重現：

| 級別 | 名稱 | 判定條件 |
| --- | --- | --- |
| 1 | 陳述主張 | 預設層級 |
| 2 | 提出理由 | 出現因果或條件連接詞，或篇幅超過 60 字 |
| 3 | 援引證據或反例 | 有反例／證據語／使用「這個理論無法解釋」支架，**且**已達第 2 級條件 |
| 4 | 綜整並改進理論 | 使用「更好的理論」或「綜合我們的知識」支架（或本身是躍升貼文），**且**有修正語、引用、收攏其他貼文，或用到 3 個以上領域詞彙 |

線索詞表定義於 `EPISTEMIC_CUES`，領域詞彙表定義於 `DOMAIN_TERMS`，兩者都可依學科替換。

### 4.5 知識建構指數（KBI）

以班級最大值正規化後加權合成，值域 0–100：

| 成分 | 權重 |
| --- | --- |
| 貼文量 | 15% |
| 延伸他人 | 20% |
| 被他人延伸 | 15% |
| 閱讀廣度 | 10% |
| 支架多樣性 | 10% |
| 論述層次 | 20% |
| 領域詞彙 | 10% |

**貼文量的權重刻意壓低**：知識建構的重點是想法有沒有被改進，而不是誰貼得多。
權重是本系統的設定值，不是既有文獻的標準，研究上使用時請明確說明並做敏感度分析。

### 4.6 雙軌評量分區

以班級中位數切分 Δθ（後測 − 前測）與 KBI：

| 分區 | 條件 | 教學意涵 |
| --- | --- | --- |
| **A 共構轉化** | Δθ 高、KBI 高 | 討論確實轉成了理解 |
| **B 論述未轉化** | Δθ 低、KBI 高 | 貼很多但沒跟上——檢查是否只在附和，沒有真的改寫自己的理論 |
| **C 個別成長** | Δθ 高、KBI 低 | 沉默的高手，最好的知識資源人選 |
| **D 需要介入** | 兩軌都低 | 優先安排小組角色與具體任務 |

B 與 C 是兩種完全不同的教學處方，而它們在任何單軌系統裡都看不見——
這是本系統要求「兩軸一起看」的直接理由。

**注意**：Δθ 帶有測量誤差。若某位學生的 Δθ 小於其 θ 標準誤的兩倍，不應解讀為真的進步。

### 4.7 模組化提示與回合排程

腳本不是「3 角色 × 3 歷程各寫一份」，而是拆成 8 個模組，執行時組合其中 3 個：

| 模組 | 數量 | 內容 |
| --- | --- | --- |
| 系統骨幹 | 1 | 任務規則與防洩答機制（四條件共用） |
| 角色 | 3 | **只有社會框架**，不含任何提問內容 |
| 認知歷程 | 3 | 提問功能與該歷程的子歷程提問庫 |

這個設計讓「提問功能跨角色恆定、僅社會框架隨角色而異」成為**可以逐字查核的事實**，
也讓鷹架機會、資訊量與任務目標在三個條件之間保持恆定。

**回合排程**：AI 的回應型態由回合數決定，不讀取任何學生端的編碼函式，
也不指定學生下一步該用什麼策略——學生的歷程轉移因此反映他自己的選擇，
不含對 AI 指令的遵從成分（prompt compliance）。

| 回合 | 提問功能 | 做什麼 |
| --- | --- | --- |
| 1 | 目標澄清 | 請學生說出這一題在問什麼 |
| 2 | 依據索引 | 請學生指出用到題目裡的哪一個條件 |
| 3 | 歷程提問 | 依該題官方標定歷程的子歷程提問庫提出一問 |
| 4 | 反向檢核 | 請學生說明什麼情況下他的做法會不成立 |
| 5 | 延伸歷程 | 往上一層歷程取一個子歷程提問 |
| 6 | 收束整理 | 請學生用一句話說出現在的想法 |

每題上限 6 次學生發話；第 7 次起系統以固定語句告知額度用盡並停止回應，換題後重新計算。

**防洩答攔截**：每一則夥伴發話送出前都會篩檢判定詞（答對／答錯／正解是／應該選…）、
正解字串與正解代號，命中即攔下並改為固定語句。規則引擎本來就不會產生這些內容，
這一關是為外部語言模型準備的——**攔截次數本身即為可報告的實施忠實度指標**。

**離線也能跑三條件**：正因為提問功能與提問庫跨角色共用、只有社會框架不同，
規則引擎（`agentTurn()`）就能忠實產生三種條件的對話，不必依賴語言模型。
這對研究是一項實質優勢：對話內容完全可重現，且不受模型版本更迭影響。

### 4.8 相對歷程編碼

以「試題官方標定之歷程」為判定基準，把學生的每一次發話編碼為三類：

| 編碼 | 意義 |
| --- | --- |
| `BELOW`（Q−） | 發話的認知層次**低於**該題所要求的歷程 |
| `AT`（Q0） | 與該題歷程**相同** |
| `ABOVE`（Q+） | **高於**該題歷程——學生自發地把問題往上推 |

發話的認知層次由線索詞判定（`PROCESS_CUES`）。`ABOVE` 比例是 AaL 主張
「學生是主動行動者」最直接的行為證據：在只要求「知道」的題目上談起了推論或論證。

### 4.9 延宕序列分析（LSA）

以「同一位學生 × 同一題」為一段序列，段與段之間不計轉移。
十種行為編碼：標記題幹 `M`、選項點選 `O`、書寫作答 `W`、
發話 `Q−`／`Q0`／`Q+`、代理人回應 `A`、寫筆記 `N`、自我檢核 `C`、送出 `S`。

調整殘差（Bakeman & Gottman）：

```
z = (F − E) / √( E · (1 − Rᵢ/N) · (1 − Cⱼ/N) ),   E = Rᵢ·Cⱼ/N
```

|z| ≥ 1.96 視為顯著；正值為促進性轉移，負值為抑制性轉移。
平台可分條件計算，也可匯出 GSEQ 的 SDIS 格式交給專用軟體覆核。

### 4.10 認知網絡分析（ENA）

* **單位**：學生（每一點是一個人的「人—AI 認知互動網絡」）
* **編碼**（8 項）：知道 `K`、應用 `A`、推理 `R`、援引依據 `EVID`、
  自我監控 `MON`、修正 `REV`、正向情緒 `POS`、負向情緒 `NEG`
* **stanza**：同一題內的移動窗（預設 4 行）
* **累積**：窗內兩兩編碼共現計數 → 每位學生一個鄰接向量（28 維）
* **正規化**：球面正規化（除以向量長度）
* **降維**：對中心化後的資料以冪迭代求共變異數矩陣的前兩個主軸（等價於 SVD）

平均網絡以各條件單位向量的平均繪製，節點採**固定圓形佈局**。
正式分析請以 R 的 `rENA` 套件重跑並採用共註冊（co-registration）佈局；
平台的「資料匯出 → rENA 寬表 CSV」已提供符合 `ena.accumulate.data()` 輸入格式的檔案。

### 4.11 情感分析

詞典法：正負向詞計數，程度副詞加權 ×1.5、否定前綴反號，除以 3 後截斷於 ±1。
對照組沒有對話，改採其「我的筆記」文字，使四條件可比較。

兩層用途：對內用於辨識與校正作答情緒對測量的干擾；
對外可發展為**去識別化的情緒儀表板**——平台的儀表板刻意只到班級層級，
個人情緒不回饋給同儕，避免把情緒變成另一種被評比的東西。

詞典法對反諷與脈絡依賴的表達無能為力，正式分析需要人工標註的信度檢核。

### 4.12 共變數分析與中介路徑

**ANCOVA**：以條件為因子、對應前測分數為共變數，以虛擬編碼的 OLS 完整模型
與僅含共變數的簡化模型相比，取 SS 差計算 F 與 partial η²；
調整後平均為共變數總平均處的預測值；事後比較的標準誤採

```
SE = √( MSE · (1/nᵢ + 1/nⱼ + (x̄ᵢ − x̄ⱼ)² / SSw(x)) )
```

並以 Bonferroni 校正。p 值採 Wilson–Hilferty 近似（t² ~ F(1, df)）。

**平行多重中介**（PROCESS Model 4 的觀察變項版本）：
`a` 路徑由「條件 → 各中介」的迴歸取得，`b` 與 `c′` 由「條件 + 所有中介 → 結果」的迴歸取得，
間接效果 `a·b` 的信賴區間以百分位 bootstrap（預設 1200–1500 次重抽）求得，
CI 不含 0 即視為顯著。

**兩項必須聲明的限制**：(1) 這是觀察變項路徑模型，不是含潛在變項的 SEM；
(2) 條件在**班級層次**操弄，本模組以學生為分析單位，未處理班級內相依——
嚴謹分析應採多層次模型並報告 ICC 與設計效應。

## 5. AI 助評的雙引擎設計

這是本系統在研究上最刻意的一項設計。同一份材料（`materialClass`／`materialNote`／
`materialThread` 產生的文字）同時提供給兩套引擎：

| | 內建規則引擎 | 外部語言模型 |
| --- | --- | --- |
| 執行環境 | 完全離線 | OpenAI Chat Completions 相容端點 |
| 可重現性 | 100%（同資料同輸出） | 否（同資料兩次結果可能不同） |
| 可追溯性 | 每一句都能追到 Rasch 估計值或誘答標記 | 否 |
| 彈性 | 只能處理有標記的情況 | 能處理沒有標記的例外 |
| 語言自然度 | 樣板化 | 高 |

規則引擎之所以做得到概念層次的診斷，關鍵在**誘答選項掛了迷思代碼**
（`ITEMS[].why = {選項索引: 迷思代碼}`）。命題時多花的這一步，
換來的是完全可重現、可寫進研究方法章節的分析結果。

**研究上的建議用法**：同一份資料兩套引擎各跑一次，再加上人工判讀，
做「人—規則—模型」三方比對，用來檢視語言模型在教育診斷上的增益與風險。

八個助評功能：

1. `aiClassMisconception` — 全班迷思深度分析（含「轉為共構問題」段落）
2. `aiItemStrategy` — 單題教學策略（含概念錯／程序錯／策略錯判斷）
3. `aiRubric` — 非選題評量規準（三向度配分＋常見錯誤扣分）
4. `aiSimilarItems` — 相似題生成
5. `aiNoteFeedback` — 貼文形成性回饋（貢獻／層次／下一步，不給答案）
6. `aiThreadSynthesis` — 想法串綜整與躍升貼文草稿
7. `aiCommunityReport` — 社群知識建構報告（含評量上的提醒）
8. `aiItemsFromDiscourse` — 由討論命題

所有輸出都會依 `功能:對象:引擎` 快取在 `state.aiCache`，並隨研究資料一起匯出。

## 6. 資料模型

```js
state = {
  version, users[], classes[], assignments[], responses[], submissions[],
  views[], notes[], settings{}, aiCache{}, ui{}, unitOverrides{}
}

note = {
  id, viewId, title,
  segs: [{s: 支架代碼, text}],      // 一則貼文可含多個支架段落
  authorIds[], keywords[], createdAt, editedAt, revisions,
  x, y,                              // 視圖上的座標（可拖曳，會存下）
  kind: 'note' | 'problem' | 'rise',
  buildOn,                           // 延伸自哪一則
  contains[],                        // 躍升收攏了哪些貼文
  refs: [{noteId, quote}],           // 引用（保留原句）
  itemRef: {aid, iid},               // 連結的題目
  reads[], annotations[]
}

view = { id, title, desc, createdAt, origin: {aid, iid, mis} | null, links[] }
```

`origin` 是橋接留下的血緣記錄；`itemRef` 讓個別貼文也能掛回題目。
這兩個欄位讓「測驗資料」與「論述資料」在分析時可以 join。

## 6.5 問卷工具與研究設計參數

**五項動機性構念**（前後測）：

| 構念 | 維度 | 題數 | 量尺 | 施測 |
| --- | --- | --- | --- | --- |
| 內在動機 / 外在動機 | 學習動機 | 4 / 3 | 六點 | 前 + 後 |
| 自我效能 | 自我效能 | 8 | 六點 | 前 + 後 |
| 內在 / 外在 / 增生負荷 | 認知負荷 | 3 / 3 / 3 | 六點 | 僅後測（任務中產生的狀態） |
| 行為 / 情緒 / 認知投入 | 學習投入 | 4 / 4 / 4 | 五點 | 僅後測 |
| 學習焦慮 | 學習焦慮 | 5 | 六點 | 前 + 後 |

後測另含**角色知覺操弄檢核**（3 題，對照組不施）與**系統使用感受**（3 題）。

> **重要聲明**：平台內建的題項是依各構念定義**自撰**的情境化示範題，
> 目的是讓施測與計分流程完整可跑，**不是**已驗證量表的中譯本。
> 正式施測請改用已於臺灣學習者樣本完成中譯與信效度驗證的公開量表
> （MSLQ 中譯之內外在動機與自我效能、Leppink 三因素認知負荷、
> Fredricks 三維學習投入、MSLQ 考試焦慮分量表），
> 並完成專家審查與學童認知訪談。這一點在平台的問卷頁面上也有常駐提示。

**叢集隨機分派**：條件在**班級層次**操弄——同一班的學生分派到同一個條件，
避免同班同學互相看到不同夥伴而造成擴散污染。分派在年級內進行區組，
每次分派的亂數種子都會寫入 `state.assignmentLog`，分派可以完全重現。

示範資料為 4 班 × 24 人 = 96 人，四條件各 1 班；四班共用同一份題本、
**同一次 Rasch 校準**，條件之間才可比較。

## 7. 研究資料匯出

「雙軌評量儀表板 → 匯出研究資料」產生的 JSON 約 180 KB，包含：

* `users` / `classes` / `units` / `items` / `misconceptions` / `scaffolds` — 完整編碼簿
* `assignments` / `responses` / `submissions` — 原始作答矩陣
* `diagnostics.pre` / `diagnostics.post` — 每人 θ、SE、Infit；每題 δ、Infit、Outfit、
  迷思率、誘答分布；以及每一個「人×題」的象限判定與預期答對機率
* `views` / `notes` — 完整貼文語料，每則附上論述層次與命中的領域詞彙
* `discourse` / `network` / `community` — 論述指標、延伸網絡、社群摘要
* `dualTrack` — 每人的 Δθ、KBI 與分區
* `aiOutputs` — 所有 AI 助評的原始輸出（含引擎標記）

另可匯出下列檔案，各自對應到不同的分析軟體與研究問題：

| 檔案 | 內容 | 對應 RQ | 讀進哪裡 |
| --- | --- | --- | --- |
| `kidforum-responses.csv` | 長格式作答，附 θ、δ、四象限 | RQ1、RQ7 | R（`eRm`、`TAM`）、SPSS |
| `kidforum-surveys.csv` | 每人每構念一列的問卷分數 | RQ2、RQ3 | R、SPSS、Mplus |
| `kidforum-sequences.sdis` | GSEQ 的 SDIS 事件序列 | RQ4 | GSEQ |
| `kidforum-telemetry.csv` | 每人每題的遙測摘要（首鍵延遲、擊鍵、刪除、長停頓、標記、檢核、停留） | RQ4 | R、SPSS |
| `kidforum-ena-lines.csv` | 一列一個事件／對話回合，附二元編碼欄 | RQ5、RQ6 | R（`rENA`） |
| `kidforum-research-data.json` | 完整資料包（約 7 MB，含編碼簿、8 個提示模組全文、所有衍生指標與 AI 輸出） | 全部 | 任何 |

SDIS 的編碼名稱不接受非 ASCII，匯出時自動轉為安全代號
（`MARK` / `OPT` / `WRITE` / `QLOW` / `QAT` / `QHIGH` / `AGENT` / `NOTE` / `CHECK` / `SUBMIT`）。

**示範日誌不寫進 localStorage**，而是每次載入時由固定種子重算——
可重現、不占儲存空間，且不會因為瀏覽器配額而遺失；
使用者自己操作產生的事件才寫入 `state.logs` 並一起匯出。

## 8. 可能的研究問題

1. 由 KIDMAP 第 II 象限自動生成的探究問題，與教師自行擬定的問題相比，
   在貼文參與度、論述層次與後測 Δθ 上是否有差異？
2. 「知識資源人」機制（指名第 I 象限學生先發言）是否改變了建構網絡的中心性分布，
   降低少數人壟斷討論的情形？
3. 規則引擎與語言模型對同一批貼文的論述層次評定，一致性如何？
   兩者與人工評定的相關與偏誤各是什麼樣子？
4. 雙軌分區中的 B 區（論述多但 Δθ 低）學生，其貼文在語言特徵上與 A 區有何系統差異？
5. 「由討論命題」產生的後測題，其難度與鑑別度是否可用？
   學生在這些題目上的表現是否比在原始題組上更能反映共構的成果？

## 9. 限制

* 本原型內建的班級、學生、作答與貼文**全部是模擬資料**，由固定亂數種子產生，
  每次載入結果一致，僅供展示與方法討論，**不得當成實徵結果引用**。
* 題目為仿會考題型的自編題，**不是官方原題**。
* 論述層次是規則判定，會低估口語表達好但書寫少的學生，也會被刻意堆砌連接詞的貼文抬高。
  任何用於成績的用途都必須有人工複核。
* **問卷題項是自撰示範題，不是已驗證量表**（見 §6.5）。
* **條件在班級層次操弄，本平台的 ANCOVA 以學生為分析單位**，未處理班級內相依。
  嚴謹分析應採多層次模型，並報告 ICC 與設計效應。
* 效果檢定的 p 值採 Wilson–Hilferty 近似；中介估計的是觀察變項路徑模型，不是 SEM。
  兩者都請以 lavaan／Mplus／SPSS 覆核。
* ENA 的節點採固定圓形佈局，不是 rENA 的共註冊佈局。
* 相對歷程編碼與情感分析都是規則判定，正式研究需要人工標註的信度檢核
  （建議至少雙人編碼一成樣本並報告 Cohen's κ）。
* 示範日誌的四條件差異是**依理論預測寫進生成器的**，用來示範分析管線能不能把差異抓出來，
  不是實徵發現。任何從示範資料讀出的效果量都沒有實質意義。
* 以國中／國小學生為對象的生成式 AI 互動涉及知情同意、資料最小化與人為監督；
  實際施測前需完成倫理審查，並明確告知哪些指標會、哪些不會用於成績。
* 簡化 Rasch 模式的假設見 §4.1。
* 資料存放在瀏覽器的 `localStorage`，換裝置或清除資料就會消失。
  真實課堂使用需要接後端與帳號系統（見 §11）。
* 數學式以 Unicode 字元排版（`x²`、`√`、`±`），未引入 KaTeX。
  若需要完整 LaTeX 排版，可在 `md()` 之後加一層數學渲染。

## 11. 要用在真實課堂還缺什麼

1. **後端與帳號**：目前的 `localStorage` 只能單機示範。
   來源平台用的是 Supabase（Postgres + Auth + Row Level Security），
   本系統的資料模型可以直接對應成資料表，`state` 的每個陣列即一張表。
2. **即時協作**：知識建構空間需要多人同時上線，貼文與拖曳要即時同步。
3. **題庫授權**：需要正式取得歷屆會考題目與圖檔的使用授權。
4. **迷思代碼的建置**：規則引擎的診斷品質完全取決於誘答選項的標記品質，
   這需要由學科教師以專家共識方式建立，並做編碼者間信度。
5. **倫理審查**：學生的貼文是可辨識的個人資料，論述指標又會被用於評量，
   實際施測前需要 IRB 審查、學生與家長同意，並明確告知哪些指標會、哪些不會用於成績。
